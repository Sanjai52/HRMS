# HRMS Premium UI Revamp — Implementation Plan

> **For agentic workers:** Use `superpowers:subagent-driven-development`. Execute one task at a time, with a fresh implementer sub-agent and a task review before the next task. Steps use checkbox syntax. The controller owns shared files and the final review.
>
> **Execution state:** Choice **A** approved — full Velura-derived emerald product system. Work stays on `ui-tweaks`. **Do not commit** until the user explicitly approves the finished branch. Do not merge to `main`.

**Goal:** Translate Velura's emerald/slate design language into every HRMS user-facing surface, and replace technical/back-end leakage with human, action-oriented copy. No stack change, no new UI library, no raw IDs.

**Architecture:** Next.js 15 App Router + React 19 + Tailwind v4 `@theme` + Phosphor icons. The design system is expressed as semantic CSS tokens, a small primitive layer, one app shell, and page recipes. Velura's Tailwind v3/shadcn implementation is **not** copied — only its visual language, measurements, and information hierarchy.

**Tech stack:** Next.js 15.1, React 19, Tailwind CSS 4.3 (`@tailwindcss/postcss`), `@phosphor-icons/react` 2.1, TypeScript 5.6. DM Sans is added via `next/font/google` (variable, latin subset).

**Specs and references:**
- `docs/Velura-vs-HRMS.md` — verdict, 18-dimension comparison, token translation, rollout.
- `docs/Velura-Design.md` — Velura foundations, primitives, marketing, app-shell, dashboard recipes, quirks not to copy.
- `docs/ui-content-policy.md` — hard bans, error taxonomy, identifier rules, exact copy.
- `docs/current-design.md` — HRMS as-is baseline.
- `docs/ui-audit-errors-ids.md` — produced by the audit task; authoritative list of leak sites.
- `docs/ui-surface-inventory.md` — produced by the audit task; authoritative page/wave map.

## Global Constraints (non-negotiable)

1. **Design direction A:** emerald product primary `#047857`; deep slate ink `#0F1729`; canvas `#F8FAFC`; white surfaces; 6px controls; 8px cards/panels; DM Sans. Coral `#FF5A5F` survives only as the logo/brand mark and rare brand moments — never as a product action color.
2. **Contrast:** primary button `#047857` + white = 5.48:1 (passes AA). Never use `#129174` for text or a button fill. Secondary text `#637288` on white = 4.75:1. Do not use lighter grey for body copy.
3. **Fonts:** DM Sans variable, weights 400/500/600. No weight below 400, no weight 800, no `font-extralight`. Body is 14px, not 15px. Page title is 25px/600, not 28px/800. Marketing display may reach 56px/600.
4. **Geometry:** buttons/inputs 6px radius; cards/panels 8px; status pills may be full. Delete 12px cards, 3xl/4xl card radii, and pill-shaped action buttons.
5. **Elevation:** one card shadow (`--shadow-card`), one popover shadow (`--shadow-pop`). No stacked shadows, no glassmorphism in the product, no gradients behind data tables.
6. **Icons:** Phosphor only, 16/18/20px, `weight="regular"` or `"bold"` for active nav. No emoji as UI icons. No icon-only button without an accessible label.
7. **Content:** `docs/ui-content-policy.md` applies to every page. No raw `error.message`, HTTP codes, endpoint paths, JSON, SQL/Prisma text, log lines, metrics `<pre>` blocks, tokens, UUIDs, or database IDs. Every error has a next step.
8. **No backend behavior changes.** This is a UI revamp. Do not change API contracts, database schema, auth rules, or business logic. If a UI need requires backend data, hide/replace the element instead of inventing data.
9. **No new dependencies.** DM Sans via `next/font` is the only addition. Do not add shadcn, Radix, lucide, framer-motion, clsx, or a chart library.
10. **Light theme only** for this phase. Do not add a theme toggle or dark variants.
11. **Verification is Playwright MCP only.** Do not write or run Playwright e2e scripts (`npm run e2e` is forbidden for this work). Do not reset/reseed the dev database. Do not stop or restart the API/database.
12. **No commits.** Leave changes in the working tree. The controller reviews file-scoped `git diff` output. The final merge waits for explicit approval.
13. **Shared-file ownership:** only the task named in the ownership table may edit `globals.css`, `layout.tsx`, `components/ui.tsx`, `components/app-shell.tsx`, `components/feedback.tsx`, `lib/api.ts`, `lib/hr.ts`, `lib/errors.ts`, `lib/format.ts`. A surface task that needs a shared change stops and reports the gap.
14. **Responsive floor:** every surface must work at 390×844 and 1440×900. Tables may scroll horizontally inside a bordered container; the page itself must not scroll horizontally.
15. **States:** every data surface has loading (skeleton, not spinner), empty (human explanation + action), error (friendly `ErrorState` + retry), and success. Forms show field-level validation and move focus to the first invalid field.
16. **Accessibility:** visible `focus-visible` ring (2px emerald-600, 2px offset), semantic table headers, `aria-current="page"` on active nav, `aria-busy` while loading, `role="alert"` on errors, 44×44 minimum touch targets on mobile, no color-only status.
17. **Scope:** `apps/web` only. `apps/candidate-portal` (`:4100`) is fixture HTML and out of scope. Do not copy Velura assets, logo, wordmark, copy, fonts other than DM Sans, or code.
18. **Untracked reference material** (`Reference/`, `.playwright-mcp/`, design docs) must not be modified by implementation tasks except reading. Never delete it.

### Step 4.1 — One HTTP core

Create a private `requestJson<T>(path, init, token?)` in `lib/api.ts` (export it for `hr.ts`). It must:

1. Build the URL from `NEXT_PUBLIC_API_BASE` (default `http://localhost:4000`).
2. Attach credentials, content-type, bearer token, CSRF from `sessionStorage`.
3. On `429` throw `ApiError(429, "RATE_LIMIT", "Too many attempts. Wait a moment and try again.", raw, true)`.
4. On `401` throw `ApiError(401, "UNAUTHORIZED", "Your session has expired. Sign in again.", raw, false)`.
5. On other non-OK: parse the body safely (`await res.json().catch(() => null)`); extract `error.code`/`error.message` into `technicalMessage` only. Never use the backend message as `userMessage`.
6. Map status → safe copy per `docs/ui-content-policy.md`. 400/422 → "Check the highlighted fields."; 403 → "You don't have access to this."; 404 → "We couldn't find that record."; 409 → "This record has changed. Refresh and try again."; 5xx → "Something went wrong on our side. Try again in a moment."; unknown → "Something went wrong. Try again."
7. On fetch rejection (`TypeError: Failed to fetch`, abort), throw `ApiError(0, "NETWORK", "We couldn't connect. Check your connection and try again.", raw, true)`.
8. `console.error` the technical error **only** when `process.env.NODE_ENV !== "production"`; never return it in the user message.
9. Parse success as `{ data: T }`; keep `hr.ts`'s `{ data, meta }` shape by adding a `requestEnvelope` variant rather than duplicating fetch logic.

`lib/hr.ts` keeps its public exports (`authed`, `hrGet`, etc. — preserve existing names) but delegates to the core; do not change call sites just for the import.

### Step 4.2 — `toUserMessage`

`toUserMessage` accepts an `ApiError`, a DOMException/network error, or unknown. Return the policy title/body/action. Preserve a caller fallback title for context: `toUserMessage(err, "We couldn't load your team")` returns that title with the taxonomy body. Never accept or return raw text.

### Step 4.3 — Formatters

### Step 5.1 — Errors

For each `catch`/`.catch`:
```ts
// before
.catch((err) => setError((err as Error).message));
// after
.catch((err) => setError(toUserMessage(err, "We couldn't load your team").title + ". " + ...));
```
Prefer storing the `UserError` object, not a concatenated string:
```ts
const [error, setError] = useState<UserError | null>(null);
...
<ErrorState title={error.title} body={error.body} actionLabel="Try again" onAction={load} />
```
If a page uses a single `error` string and a redesign is out of scope, store `toUserMessage(err).body` only (safe), never the raw message. Inline API failures use `Alert tone="danger"` with the safe body.

**Contexts for fallback titles:** employees → "We couldn't load your team"; attendance → "We couldn't load attendance"; leave → "We couldn't load leave requests"; payroll → "We couldn't load payroll"; performance → "We couldn't load performance"; recruitment → "We couldn't load recruiting"; reports → "We couldn't load this report"; notifications → "We couldn't load notifications"; admin → "We couldn't load this admin page"; settings/profile → "We couldn't save your changes" for mutations.
